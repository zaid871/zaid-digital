# Repost ("second chance") loop (2026-10-29, user-approved: auto repost with limits)

When a published IG Reel clearly underperforms the account's own recent
baseline, the system analyzes it (hypothesis-labeled, never causal),
builds a new-caption variant, and auto-republishes it at a best-time
slot.

## How it runs

Daily 07:30 IST, `n8n/workflows/affiliate/performance-repost.json`
(33 nodes, generated by `scripts/gen-performance-repost.py`):

1. `sweep` calls `POST /api/v1/publishing/sweep` — the backend loads
   published IG Reels from the last 7 days (older than 24h, originals
   only), reads each one's lifetime insights from the Meta Graph API,
   builds the account's own baseline (medians), flags underperformers,
   and creates variant records + `build-variant` worker jobs (max 2
   per run).
2. Per variant: poll `GET /api/v1/publishing/variants/[id]` until the
   worker marks it `ready` (30 min cap, then parked).
3. Best-time gate — off-peak variants wait for the next IST slot.
4. Publish: same video, new caption (+ affiliate disclosure), via the
   standard container → poll → media_publish path.
5. The new media ID is written back to the variant record, linked to
   the original via `variantOf`.

## Analysis honesty (src/lib/publishing/repost.ts)

- Baselines are medians of the account's OWN recent posts only — no
  outside benchmarks. Underperforming = views < 40% of median views.
- Every explanation is `kind: "hypothesis"` with the observed numbers
  cited; data never proves a cause. An honesty footer ships with every
  analysis ("ye wajah pakki nahi hai — variant ek experiment hai").
- Missing metrics = `insufficient_data`, never zeros. A baseline of
  fewer than 3 posts flags nothing.
- Rule-based hypotheses: low reach + ok engagement → timing/hook
  hypothesis; low engagement rate → caption/content hypothesis; very
  low views → hook hypothesis.

## Limits (all enforced)

- 1 variant per original; variants never get variants.
- Repost only after the original is 48h+ old.
- Max 2 variants per sweep run (IG also enforces a daily publishing limit).
- Variant caption comes from the caption pack (price/banned-claim
  fields dropped, never fabricated). If no usable caption survives,
  the variant parks as `needs_review` and NEVER auto-publishes.
- Variant also fails → parked, no infinite loop.

## Supporting changes

- Prisma: `PublishRecord` += `videoUrl`, `variantOf` self-relation;
  statuses += `building | ready | needs_review`. Migration
  `20261029210000_repost_variant`; client regenerated.
- Endpoints: `POST /publishing/records` (upsert/update),
  `POST /publishing/analyze` (pure analysis, no side effects),
  `POST /publishing/sweep`, `GET /publishing/variants/[id]`.
  All n8n-called routes use the `x-n8n-secret` check
  (`src/lib/api-auth.ts`, mirrors stage-callback).
- Worker: `build-variant` job on the video queue →
  `src/lib/publishing/variant.ts` (caption pack + compliance + park rules).
- `instagram-publishing.json` / `facebook-publishing.json`: appended a
  `record-publish` node after the success log so the monitor has real
  records (idempotent upsert by platform+mediaId).
- `.env.example` + `deploy/assistant-deploy.sh`: added `IG_USER_ID` /
  `IG_ACCESS_TOKEN` slots (same values n8n already uses; the backend
  sweep needs them for insights reads).

## Honest caveats

- Publishes made BEFORE the `record-publish` node exists have no
  backend records — the monitor only covers publishes from then on.
- The "reason" is always a hypothesis; the fix is an experiment, not
  a guaranteed cure. Variant performance feeds the analytics loop.
- Deploy-time: import the new workflow in n8n, fill the two IG env
  vars on the backend, run `prisma migrate deploy`.
- Meta insights for very new media can lag — the 24h minimum age
  absorbs most of that.
